# internal/repos/

The one list of repositories the dot works on. `repos.yaml` is the source; this
package parses it, resolves defaults and profiles, runs the features, and
renders the files the other tools read. `cmd/repos` is its CLI and the
dashboard calls it when it saves `repos.yaml`. ADR 0022.

| File | Holds |
| --- | --- |
| `repos.go` | `Document`, `Parse`, `Resolve`: top-level keys, `defaults`, `profiles`, `use`, merging |
| `features.go` | the `Feature` interface, its `base` defaults, the registry, `Generate` |
| `features_builtin.go` | `checkout`, `tend`, `review`, `reply`, `fix_ci`, `fix_issue`, `provider` |
| `features_sync.go` | `sync`: a feature that owns one extra generated file |
| `emit.go` | `Render`, `Write`, `Diff`, `Build`, settings merging |
| `importer.go` | `Import`: builds a repos.yaml from awf-gh.yaml, tend.list, repos.map, sync.map |

## ADD A FEATURE

A feature is one key under a repository. To add one:

1. Create `features_<name>.go` with a type that embeds `base` and implements
   `Key`, `Doc`, `Check` and `Emit`, and `Register` it from `init`.
2. `Check` validates the value after defaults and profiles are applied. A `true`
   arrives as an empty mapping; a list of blocks arrives as a list.
3. `Emit` adds to the `Output`: a watcher `Rule`, a `TendEntry`, a
   `CheckoutEntry`, or lines of a file the feature owns in `Output.Files` (the
   name is the generated file; it gets the standard header).
4. To change what other features emitted for the same repository (as `provider`
   does), override `Modify`; it runs after every `Emit` of that repository.
5. To make `bin/repos import` recognise an existing rule, override `Workflow` (the
   awf-gh workflow the feature owns), and teach `importer.go` any other file.
6. Test it: `TestAFeatureCanBeAddedWithoutTouchingTheLoader` shows the shape. If
   the feature reads a file `bin/repos import` should absorb, add it to
   `testdata/` and the round trip test.

The loader never learns a key's meaning: an unknown key is an error that names
the known ones, so a typo cannot switch a feature off quietly.

## RULES

- A default supplies values; it never switches a feature on. Only a plain value
  (such as `provider: claude`) applies to every repository. `false` switches a
  profile's key off for one repository.
- Generated files carry a "Generated by bin/repos" header and are written only
  when their content changed, through a temporary file and a rename.
- `awf_url` and `state_path` are not in `repos.yaml` by default: `bin/configure`
  chooses them by mode. The generator keeps what the generated `awf-gh.yaml`
  already has, unless a flag or `settings` says otherwise.
- A watcher rule names only events awf-gh knows (`events` in
  `features_builtin.go`); `issue-labeled` needs a label. A wrong one would stop
  the whole polling pass, so it is refused here.
- Never put real repository names in tests or `testdata/`: the fixtures use
  `acme/*` and `upstream/*`.
- The round trip test is the contract of `import`: regenerating the imported file
  must give the same rules, tend lines and checkouts, and importing the result
  again must change nothing.
